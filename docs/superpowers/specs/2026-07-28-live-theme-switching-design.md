# Codex 主题热切换设计

## 目标

在管理器以 CDP 模式连接的 Codex 窗口中，通过主题库或托盘菜单切换主题时，不重启 Codex、不刷新页面，并保留当前任务与输入内容。未连接 CDP 时仍保存主题选择，并标记为下次主题版启动时应用。

## 交互

- 主题库中的非当前主题按钮表示立即切换；当前主题按钮表示恢复原生外观。
- 托盘菜单增加“切换主题”子菜单，包含“原生外观”和所有已安装主题，当前选项显示单选勾选。
- 两个入口调用同一切换服务。托盘切换后向已打开的管理器窗口推送最新快照。
- 切换期间拒绝重复操作；失败时保留或恢复原主题，并在诊断状态中暴露错误。

## 架构

`LiveThemeSwitcher` 负责持久化选择和调用运行时。它在切换前记录旧主题；新主题注入失败时恢复旧配置，运行时负责恢复旧注入。

`ThemeRuntimeCoordinator` 新增同一 CDP 会话内的 `switchTheme` 与 `clearTheme`。切换时安装新 early script、应用新计划，成功后移除旧 early script；失败时移除新计划并重新应用旧主题。它不关闭页面会话，不重新启动 Codex。

`buildTrayMenuTemplate` 根据 `ManagerSnapshot` 生成动态菜单，所有菜单动作委托给主进程的统一切换函数。主进程在主题列表或当前主题变化后重建托盘菜单，并通过 IPC 事件同步管理器界面。

## 状态与失败处理

- 有开放 CDP 页面会话：成功切换后状态为 `applied`，更新运行 ID与适配器 ID。
- CDP 尚未连接：保存选择，状态为 `pending`，不报失败。
- 新主题应用失败但旧主题恢复成功：持久化配置恢复旧主题，操作向调用者失败。
- 新旧主题均无法应用：运行时进入 `compatibility-degraded`，保留诊断错误码。
- 恢复原生外观时只回滚注入并清空运行时主题，CDP 页面会话可以保留供下一次即时切换。

## 验证

- 单元测试证明热切换复用同一页面会话、成功后清理旧注入、失败后恢复旧主题。
- 单元测试证明统一切换服务在无 CDP 时保存待应用状态，在失败时恢复旧配置。
- 单元测试证明托盘菜单列出主题、标记当前选择并调用正确动作。
- 界面测试证明托盘推送的快照会更新主题库选中状态。
- 完整运行 `npm test`、`npm run typecheck`、`npm run lint`、`git diff --check` 和 `npm run package`。
