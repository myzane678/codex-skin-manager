# Windows Codex 主题管理器设计

## 目标

构建一个 Windows Electron + Node 桌面端 Codex 主题管理器。它通过仅绑定 `127.0.0.1` 的 Chrome DevTools Protocol（CDP）向兼容 Codex 窗口的欢迎页注入受控视觉主题，不修改 Codex 官方安装包、`app.asar`、WindowsApps、签名或用户会话数据。

首版的重点是安全导入本地主题包、可预测地应用和回滚欢迎页主题，以及在发生兼容性或运行时错误时保持 Codex 原生可用。

## 范围

### 首版包含

- 本地文件选择器导入完整 `.codextheme` 主题包。
- 主题库展示静态预览图和主题元信息。
- 手动启用、停用和删除主题。
- 通过“Codex 主题版”快捷方式启动并在兼容欢迎页应用主题。
- 动态分配回环 CDP 端口，记录运行状态和最近 10 份日志。
- 版本范围、结构探测和保守降级。
- 默认关闭的托盘短窗口代理。
- 完整恢复默认 Codex。

### 首版不包含

- 修改官方 Codex 安装包、`app.asar`、WindowsApps、签名或官方快捷方式。
- 任意 CSS、JavaScript 注入、主题脚本、远程资源、在线字体或任意本地路径。
- URL 导入、拖拽导入、在线商店、主题编辑器、局部变量覆盖或实时主题预览。
- 主题发布者签名体系、跨设备同步、主题包自动更新或自动强制接管原始 Codex。
- 会话工作区的视觉替换，以及遮挡、重建或接管原生导航和交互。
- 强制终止无法温和关闭的官方 Codex 进程。

## 架构

采用分层运行时架构：

1. Electron 渲染层只负责主题库、导入入口、预览图、启用/停用、诊断信息和恢复入口。
2. Electron 主进程负责管理器窗口、最小化 IPC、主题版快捷方式、托盘代理开关和完整恢复命令。
3. 核心服务层负责主题包校验和存储、当前主题配置、日志、Codex 进程识别、端口分配与 CDP 注入协调。
4. 受控注入运行时只负责欢迎页节点探测、受控 CSS 生成、CDP 注入和精确回滚。

渲染层不直接访问文件系统、进程或 CDP。主题包内容不直接生成任意样式或执行逻辑；服务层将受控数据映射到固定 CSS 模板。

## 启动链路

### 主题版快捷方式

1. 管理器读取当前主题配置。
2. 核心服务优先申请 `9335`，冲突时扫描可用端口；调试端点必须仅监听 `127.0.0.1`。
3. 管理器启动或连接目标 Codex 进程，并记录 CDP 端口、Codex PID、Browser ID、启动时间和运行 ID。
4. 核心服务验证进程身份、浏览器目标和欢迎页关键节点。
5. 已启用主题且探测通过时，受控注入运行时应用主题。
6. 没有兼容窗口时，主题保持“待应用”，等待下次主题版启动。

### 原始 Codex 入口与托盘代理

默认不干预原始 Codex 入口。用户显式启用托盘代理后，代理仅在原始入口启动后的约 3 至 8 秒候选期内处理身份可验证的官方 Codex 进程：

1. 代理不按窗口标题或模糊名称猜测进程身份。
2. 可安全接管时，优先请求原始进程温和退出，再按主题版链路启动。
3. 身份不匹配、温和退出失败、超时或主题版启动失败时，代理停止接管，保持原始 Codex 可用。
4. 默认不强制结束进程；候选期结束后不再干预该次启动。

## 主题包格式和导入

`.codextheme` 是受控、非执行的 ZIP 容器，至少包含：

- `manifest.json`：主题 ID、名称、版本、作者、描述、Codex 兼容版本范围、许可证、来源标记、受控变量、布局槽位、动效声明和主题文案。
- 静态预览图。
- 在清单中声明的本地图片、GIF 和图标等素材。

清单为每项素材声明相对路径、MIME 类型和 SHA-256 哈希。主题包不允许包含或执行 JavaScript、PowerShell、EXE 或其他可执行内容；也不允许网络 URL、任意本地路径和在线字体。

导入步骤：

1. 用户通过本地文件选择器选择 `.codextheme` 文件。
2. 服务层在临时目录读取 ZIP，拒绝路径穿越、异常目录结构、缺失 `manifest.json`、未声明额外文件、缺失素材、不可识别资源类型和哈希不匹配。
3. 验证清单 schema：变量、槽位和动效仅能使用预定义白名单和值类型。
4. 所有校验通过后，将原包复制到应用专用数据目录并完整解压；运行时只引用已校验解压目录中的素材。
5. 导入成功只安装、不自动启用；没有发布者签名的主题标记为“来源未知”。

主题包仅声明变量和预定义布局槽位。管理器从固定模板生成最终 CSS，不接受主题直接提供任意 CSS。

当前启用的主题不可删除，必须先停用或切换主题。删除非当前主题时，同时删除其应用数据副本和解压资源，不影响其他主题和日志。

## 注入、兼容性和回滚

运行时状态包括：

- 原生模式：没有当前主题，不注入，托盘代理关闭。
- 主题待应用：已启用主题但没有兼容欢迎页。
- 主题已应用：目标窗口完成探测并注入受控主题。
- 兼容性降级：版本或结构探测失败，保留主题配置但不注入。
- 恢复中：正在回滚注入、关闭代理、清理快捷方式或运行时状态。

每次注入使用唯一运行 ID。注入运行时在目标窗口处于允许范围的欢迎页后：

1. 探测 Codex 版本、CDP 可用性和欢迎页关键节点。
2. 由固定模板生成 CSS，并通过 CDP 注入带运行 ID 标记的样式和装饰节点。
3. 复核注入标记、关键原生交互节点可见性和当前页面状态。
4. 任一失败立即移除该运行 ID 的样式和节点。

已验证版本在探测通过后直接应用。版本未知但 CDP 和结构均通过时应用，并显示“未验证兼容”。结构探测、连接或复核失败时不注入或立即回滚，不改变原生界面。

运行时持续关注页面是否仍为欢迎页，但不读取页面业务数据。离开欢迎页、进入会话工作区、结构变化或窗口关闭时，立即移除本次注入。原生侧栏导航、会话列表、项目选择、建议按钮、输入框、发送按钮、任务内容和窗口控制必须保持由 Codex 自身渲染和响应。

停用主题、窗口切换、异常、兼容性失败和恢复默认均只移除带当前运行 ID 的内容。重复停用和回滚必须幂等，不能影响 Codex 原有 DOM、其他窗口或用户数据。

## 恢复、日志和诊断

“恢复默认 Codex”依次执行：

1. 停用当前主题并回滚当前窗口的注入内容。
2. 停止托盘代理并清理候选观察状态。
3. 删除“Codex 主题版”快捷方式。
4. 清理当前主题配置、活动 PID、端口、Browser ID 等运行时状态。
5. 保留已导入主题包、校验后的解压资源和最近日志。

某一步失败时，其他不依赖该步骤的清理仍继续。结果分为“已恢复”“部分恢复”和“需要手动处理”，并列出具体对象和恢复操作。

服务层保留最近 10 份滚动启动/注入日志。每份日志包含启动时间、运行 ID、管理器版本、主题 ID 和版本、PID、端口、Browser ID、窗口目标标识、兼容性和节点探测结果、注入/回滚阶段、错误摘要及恢复建议。

日志不得记录会话正文、提示词、项目文件内容、认证令牌、Cookie 或完整 CDP 调试报文。诊断页面显示必要状态，并提供可复制的脱敏诊断文本。

所有错误在管理器窗口内反馈，不使用系统通知：

- 导入失败：给出校验阶段和原因，不安装主题。
- 启动失败：给出端口、进程启动或回环 CDP 连通性错误，保留主题配置供重试。
- 兼容性失败：给出版本和结构结论，不注入。
- 注入后复核失败：立即回滚，记录失败的节点或页面状态。
- 代理接管失败：不强杀原始进程，提示使用主题版快捷方式或关闭代理。
- 恢复失败：列出仍需要手动处理的项目。

## 测试策略

- 主题包校验单元测试：合法包、缺失清单、路径穿越、额外文件、非法资源类型、未知变量/槽位/动效、哈希不匹配、缺失资源和非法 URL 或本地路径。
- 配置与存储测试：导入不自动启用、当前主题不可删除、停用清空当前主题配置、原导入文件删除后主题仍可用、完整恢复保留主题和日志。
- CSS 生成测试：受控变量和槽位只产出固定模板允许的选择器和已校验资源引用；包内容不得直接拼接为 CSS 或脚本。
- CDP 协调和状态机测试：模拟进程、调试端点与页面节点，覆盖端口冲突、身份不匹配、欢迎页探测成功/失败、注入后复核失败、离开欢迎页、重复回滚和窗口关闭。
- 端到端人工验收：在已验证和未验证 Codex 版本各验证主题版启动、启用、停用、导入、删除、代理失败和恢复默认；确认原生导航、会话列表、输入发送和窗口控制始终可用，且进入会话后恢复原生外观。
- 安全回归：确认 CDP 通信只使用 `127.0.0.1`，且不修改官方程序文件或记录敏感会话内容和凭据。

## 验收标准

1. 用户可从本地选择器导入完全合法的 `.codextheme`，并在主题库看到静态预览图和“来源未知”标识。
2. 非法主题包在任意校验阶段被拒绝，应用数据目录不留下可运行安装内容。
3. 启用主题后，兼容欢迎页立即应用；没有兼容窗口时保存为待应用，并在下次主题版启动时尝试应用。
4. 主题仅影响欢迎页允许范围；进入任务会话、探测失败或停用时，注入内容完全移除。
5. 版本未知且结构通过时应用并显示兼容性状态；结构不通过时不注入且不影响原生 Codex。
6. 恢复默认 Codex 可完成主题停用、注入回滚、代理关闭、主题版快捷方式删除和运行时状态清理，同时保留导入主题和日志。
7. 任意失败都能在应用内看到阶段、原因、恢复操作和可复制的脱敏诊断信息。
