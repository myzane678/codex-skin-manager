# 当前主题侧栏提示设计

## 目标

让用户在主题库、启动与代理、恢复与诊断三个视图中都能立即识别当前启用的主题及其真实运行状态，避免只看到“主题待应用”这类缺少主题身份的信息。

## 已选方案

在侧栏底部以常驻主题块替换现有的泛化状态区。用户已选择“侧栏常驻主题块”，并接受主题尚未实际注入时使用“待启动”文案。

主题启用时，主题块显示：

- 标签 `CURRENT THEME`
- 当前主题名称
- 运行状态与 CDP 状态，例如“待启动 · CDP 已连接”
- 使用主题 manifest 中已有的 `variables.accent` 作为左侧强调色

没有启用主题时，主题块显示“当前主题”“原生模式”和 CDP 状态，不显示虚构主题名称。

## 状态文案

- `native`：原生模式
- `pending`：待启动
- `applied`：已应用
- `compatibility-degraded`：兼容性降级
- `recovering`：恢复中

CDP 状态继续显示“CDP 已连接”或“CDP 未连接”。

## 数据与组件

`ThemeView` 增加 `accent` 字段。`ManagerService` 已在生成主题视图时解析 manifest，因此直接返回 `manifest.variables.accent`，不增加新的读取或取色流程。

`App` 从 `snapshot.themes` 中查找 `active` 主题，将名称、强调色和运行状态传给侧栏主题块。提示块只负责展示，不改变启停、启动、代理或注入行为。

## 范围约束

- 不在页面标题区重复显示主题状态。
- 不修改主题卡片操作。
- 不修改运行时状态机和 CDP 逻辑。
- 不从预览图计算颜色。
- 不增加新的用户配置。

## 验证

- 单元测试证明主题视图返回 manifest 强调色。
- 渲染测试覆盖有当前主题和原生模式两种侧栏显示。
- 运行 typecheck、lint、全部测试和 Windows x64 打包。
- 启动管理器，目视确认三个视图共享同一常驻主题块且无布局遮挡。
